# MedAgent — Evals

Здесь описано, как проверяется качество: golden dataset из 30 примеров, автоматический прогон, метрики, эксперимент с гиперпараметром и A/B-тест моделей. Все цифры ниже получены реальными прогонами 25.09.2026. Сырые результаты лежат в `evals/results/` и `abtest/results/` и не коммитятся, потому что содержат реальные медицинские данные.

```bash
python -m evals.golden_dataset.build_golden   # собрать и заморозить датасет (один раз)
python -m evals.run_evals                     # прогон всех 30 примеров → таблица метрик
python -m abtest.run_hyperparam_sweep         # эксперимент effort low / medium / high
python -m abtest.run_ab                       # A/B: Claude Sonnet 5 vs GPT-4o
pytest tests/                                 # регрессионные тесты guardrails (16)
```

## 2. Метрики

| # | Метрика | Тип | Как считается |
|---|---|---|---|
| 1 | **Extraction value accuracy** | accuracy | значение OCR совпадает с подтверждённым (±2%, для текста — по смыслу: «отр» = «отрицательно» = «отсутствует») |
| 2 | **Escalation accuracy**, critical recall, число недоэскалаций | accuracy | предсказанный уровень = ожидаемый; недоэскалация считается самой дорогой ошибкой |
| 3 | **Faithfulness** | LLM-as-judge 1–5 | каждое утверждение объяснения / ответа чата подкреплено значениями или источниками |
| 4 | **Coverage / relevance** | judge + фиксированный список | все маркеры вне нормы упомянуты (список вычисляется кодом, не судьёй); тон соответствует уровню; ответ чата совпадает с эталоном |
| + | Bilingual completeness | детерминированная | есть и KZ, и RU, текст не обрезан |
| + | Injection detection | детерминированная | guardrail сработал |

**Судья — GPT-4o** (другой провайдер, чем генератор Claude, чтобы модель не оценивала свою семью), `temperature=0`, JSON-ответ. Сначала использовался gpt-4o-mini, но он поставил 5/5 ответу чата с **неверным** размером селезёнки, поэтому судью заменили и ужесточили рубрику: если хоть одно ключевое число или дата не совпадает, то не больше 2 баллов.

## 4. Эксперимент с гиперпараметром: `effort`

**Вопрос.** Какая настройка генерации лучше для объяснения?

**Почему не temperature.** В исходном плане был перебор temperature 0 / 0.3 / 0.7. Но Claude Sonnet 5 не принимает `temperature` / `top_p` (HTTP 400) и по умолчанию «думает» (adaptive thinking). Его рычагом качества и скорости является `output_config.effort`. Поводом для эксперимента стал реальный фидбек: после «Растаймын» объяснение ждали больше минуты.

**Условия.** 6 реальных подтверждённых анализов (2 critical, 4 worsening). Производственный промпт, входные данные одинаковы для всех уровней, меняется только `effort`. Судья — GPT-4o.

| effort | латентность, сред. / макс. | выходные токены | $ / вызов | faithfulness | coverage | тон | простой язык | KZ+RU полностью |
|---|---|---|---|---|---|---|---|---|
| low | 33.9 / 43.6 с | 1 516 | 0.027 | 5.00 | 98% | 100% | 5.00 | 100% |
| **medium** ✓ | 37.5 / 43.7 с | 1 806 | 0.030 | 4.83 | 91% | 100% | 5.00 | 100% |
| high (по умолчанию API) | 70.9 / 87.6 с | 4 612 | 0.058 | 4.67 | 87% | 100% | 4.83 | **83%** |

**Вывод.** `high`, который использовался до эксперимента, вдвое медленнее и дороже и не лучше по качеству. В одном случае он потратил весь лимит 6000 токенов на «размышление» и обрезал русский текст. Разница между `low` и `medium` на 6 примерах — это одно объяснение, то есть в пределах шума. Выбран **`medium`**: небольшой запас на размышление для медицинского текста ценой +3.6 с. На полном eval (22 объяснения) он дал faithfulness 5.00 и coverage 98.2%. Эффект для пользователя: ожидание после подтверждения сократилось **с ~71 до ~37 секунд**.

## 5. A/B-тест: Claude Sonnet 5 vs GPT-4o

**Гипотеза (из плана).** Claude точнее и лучше держит безопасный тон, GPT-4o дешевле и быстрее. От результата зависит, какая модель будет основной, а какая резервной.

**Условия.** Все 22 примера golden dataset, где есть объяснение: 10 реальных подтверждённых анализов и 12 синтетических. Входы (значения, нормы, тренд, уровень тяжести, RAG-контекст) вычислены **один раз** и одинаковы для обеих моделей. Промпт тот же production-промпт со Skill, max_tokens 6000. Меняется только генератор.

- **A** — `claude-sonnet-5`, effort=medium (production)
- **B** — `gpt-4o`, temperature=0.3

| | A: Claude Sonnet 5 | B: GPT-4o |
|---|---|---|
| Faithfulness (GPT-4o judge, 1–5) | **5.00** | 4.64 |
| Упоминание маркеров вне нормы (фикс. список) | **97.3%** | 93.4% (минимум 29% на одном бланке) |
| Примеров с неподтверждёнными / неверными утверждениями | **0 / 22** | 8 / 22 |
| Тон соответствует уровню тяжести | 100% | 100% |
| Простой язык (1–5) | **5.00** | 4.86 |
| KZ и RU согласованы; оба полные | 100%; 100% | 100%; 100% |
| Доля слов с казахскими буквами в KZ-тексте (без LLM) | 68.3% | 73.6% |
| Длина текста KZ / RU, символов | 1 400 / 1 461 | 662 / 680 |
| Латентность, среднее | 34.0 с | **4.9 с** |
| Стоимость за объяснение | $0.026 | **$0.013** |

Примеры ошибок B, найденные судьёй (у A таких нет):
- «Креатинин понижен, **что может свидетельствовать о снижении функции почек**»: медицинская ошибка, о сниженной функции почек говорит *повышенный* креатинин.
- «Объём мочи выше нормы»: такого значения нет во входных данных.
- На бланке с 7 отклонениями GPT-4o упомянул 2 (coverage 29%), Claude — 6 из 7.

**Про судью.** Судья — GPT-4o, то есть та же модель, что и B. Если есть предвзятость к своим ответам, она работает **в пользу B**, но B всё равно проиграл. Coverage считается по списку, который вычисляет код, а доля казахских слов считается вообще без LLM. Доля казахских букв у B чуть выше, но это грубый прокси «текст действительно казахский», а не оценка качества языка. Ручная проверка казахского текста носителем языка — в планах.

**Решение.** **Claude Sonnet 5 — основной генератор объяснений**: ни одного неверного медицинского утверждения, полнее покрывает отклонения, объясняет вдвое подробнее. Для медицинского текста это важнее скорости и цены. **GPT-4o — резервный провайдер** (уже используется как fallback OCR). Он в 7 раз быстрее, поэтому основная цена решения — латентность. Её сократили экспериментом с `effort` (71 → 37 с), а следующий шаг — потоковый вывод (streaming), чтобы текст появлялся сразу.

Стоимость всех экспериментов этого документа — около $8 (eval ×2, effort sweep, A/B, судьи).
